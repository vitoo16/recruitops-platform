# Contributing

## Workflow

1. Read `AGENTS.md`.
2. Locate the next unticked work item in `docs/plans/MASTER_PLAN.md`.
3. Confirm that work is not already implemented.
4. Load all required skills.
5. Create a focused branch.
6. Implement in small coherent changes.
7. Update docs/diagrams in the same change.
8. Run applicable quality gates.
9. Tick the exact completed plan item.
10. Use Conventional Commits.

## Branch naming

- `feat/<scope>`
- `fix/<scope>`
- `refactor/<scope>`
- `docs/<scope>`
- `chore/<scope>`

## Pull requests

A PR should:
- solve one coherent problem;
- explain why the change exists;
- list verification performed;
- include docs/diagram impact;
- call out migration/security concerns;
- avoid unrelated cleanup.
